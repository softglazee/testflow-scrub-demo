Slack channel link

Links only. A plugin cannot borrow the Slack session already open in your browser, because the API needs an OAuth token whichever client you use. What this removes is hunting for the right tab. Open the channel in Slack in a browser and paste the address bar below. The workspace and channel are read out of it.

Sends and thread reads use whichever one is selected here.

Sending, optional. An incoming webhook is the smallest thing a workspace admin can grant: post only, one channel, no reading of anything. It posts as the app rather than as you, and it still needs somebody with workspace access to add it. The URL is stored on this site and is never sent back to the browser.

This is the starting point for each person, and every row can be changed on its own. Session messages like Opening and Closing always go to the channel, they are never threaded.

Off by default. With it off, Assign copies the message as before and you send it yourself.

Reading the thread, optional. This is the bigger ask. A bot token can read the channel, so a workspace admin has to weigh that. In your own workspace you can grant it yourself in a minute. With it saved, the plugin can pull everyone who replied to the scrub thread instead of you typing their names.

With a thread link it reads that thread, which is exactly the people who answered your call for volunteers. With only the channel URL it reads the last 12 hours of the channel instead, which works but picks up anyone who happened to be chatting. To get a thread link: hover the first message of the thread, More actions, Copy link.

Pull Gutenberg issues directly

The Test Team covers more than core. The 4th Thursday session is a Gutenberg scrub, and GitHub, unlike Trac, answers a request from the plugin. So there is no export step here: pick a label and press the button.

Add tickets by id or link

Paste ticket numbers or full links, separated by commas, spaces or new lines. 46017, #46017 and the full Trac URL all work, and Gutenberg issue links are kept as they are.

One honest limit. Difficulty is read from a ticket's keywords, and keywords only arrive with a CSV export, because Trac returns 403 to anything that is not a person in a browser. So tickets added this way start with no level. Add one yourself after a pipe, like 46017 | beginner, or import the CSV later and the details fill in.

Import tickets from a Trac CSV export

Trac refuses machine requests, so the plugin cannot fetch a query itself. It can hand you the query though. Click a name below to see the tickets, or click download CSV to get the file, then drop that file in here. The columns are already chosen for you.

    If Trac shows a login screen, sign in and click the link again. Levels come from keywords: good-first-bug is Beginner, has-test-info is Moderate, anything else is Advanced.

    Drops closed tickets, anything waiting on a design or maintainer decision, anything already heading for commit, and anything with neither a patch nor written test steps. Everything dropped is listed with the reason.
